# Критерии ревью

Сверь изменения с исходным обращением, спецификацией, тикетами и согласованием человека по ссылкам из описания PR. Если ссылки нет, она недоступна или изменение выходит за согласованный объём, отметь пробел отдельно. Статусы CI и браузерный прогон относятся к ревью только при совпадении их SHA с head PR.

Выбирай глубину проверки по последствиям ошибки. Для подписи кнопки достаточно проверить смысл и видимое состояние; для расчёта слотов проверь граничные случаи и согласованность выдачи слотов с созданием записи; для прав Actions проследи, какой код выполняется, с каким токеном и где доступен секрет. Число строк в diff не определяет глубину проверки.

## Календарь

- После записи слот и все пересекающиеся слоты пропадают из доступных для всех типов встреч. Прямой запрос не может занять пересекающийся интервал; при одновременных запросах проверка и сохранение атомарны, проигравший запрос получает `409 BOOKING_CONFLICT`.
- Проверь частичное пересечение, разные длительности и смежные полуоткрытые интервалы `[start, end)`. Старт на получасовой отметке, начало не раньше 09:00 UTC, конец не позже 18:00 UTC. Окно — 14 календарных дней UTC, включая текущий; `start = now` и прошедшие слоты недоступны.
- API передаёт время в ISO 8601 (UTC); интерфейс показывает локальное время гостя. Проверь смену суток, чтобы выбранный в интерфейсе слот соответствовал тому же моменту в API.

## Отмена записи гостем ([#8](https://github.com/alex1alrus/ai-for-developers-project-387/issues/8))

- Отменяется только запись, которой принадлежит предъявленный секретный код. Код непредсказуем, не попадает в список владельца. Открытие или обновление ссылки ничего не меняет; код проверяется на сервере при явном запросе отмены. Неверный, неизвестный или отсутствующий код не меняет запись.
- Действующую запись можно отменить только при `start > now`. Для `start = now`, идущей и прошедшей записи действует отказ по времени. Повторная отмена даёт отдельный результат «уже отменена», даже если время начала прошло, и не меняет состояние.
- Отменённая запись остаётся в списке предстоящих записей владельца с явным статусом. Её интервал освобождается для всех типов встреч и в выдаче слотов, и в проверке при создании, если остальные правила соблюдены и нет пересечения с другой действующей записью.

## Контракт и GitHub Actions

- Изменения API начинаются в `spec/main.tsp`, затем выполняется `mise run gen`. `spec/generated/`, `src/api/` и `server/api/` не правятся вручную. Проверь, что реализация сервера и вызовы SDK соответствуют контракту.
- Любое расширение прав GitHub Actions или доступа к ключу модели требует отдельного решения человека. Проверь события, фильтры, SHA checkout, права каждого задания и передачу секретов по шагам.
- Принятый риск, не замечание: `review.yml` работает на `pull_request`, поэтому GitHub выполняет YAML из ветки PR. Ключ модели получают только ветки этого репозитория, а менять в них воркфлоу может только участник с правом записи и `workflows`, у которого и так есть доступ к секретам. `pull_request_target` не используется, PR из fork ключ не получают. Отмечай только изменения, которые расширяют этот круг: другие события, ослабленный фильтр автора или ветки, секрет в задании без фильтра.

## Как писать замечания

Для каждого подтверждённого дефекта укажи `файл:строка`, условие, при котором он проявится, и последствие. Если подтверждённых дефектов нет, напиши это прямо. Отдельно укажи пробелы по согласованию и проверкам. Форматирование и стиль проверяет линтер — не дублируй его замечания.
